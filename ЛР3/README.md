# ЛР3 — Нечёткие системы логического вывода

Тема примера — приоритет диагностики приложения, которое запускается с ошибками
или задержками. Выход — баллы от 0 до 100, а не вероятность отказа.

## Запуск

Нужен Python 3.10 или новее. Сторонние пакеты не требуются.
Откройте терминал в распакованной папке:

```bash
python3 нечёткая_система.py
```

На Windows можно использовать `python` или `py -3`.

## Меню

| Пункт | Что делает |
|---|---|
| 1 | Ввод одной переменной и автоматическое сравнение шести вариантов расчёта |
| 2 | Ввод трёх переменных и автоматическое сравнение четырёх вариантов |
| 3 | Расширенное сравнение четырёх импликаций с выбором агрегации |
| 4 | Показ всех переменных, термов и правил |
| 0 | Выход |

Enter выбирает значение по умолчанию. Дробные числа можно вводить с точкой
или запятой. Ошибочный ввод возвращает в меню.

## Что показать преподавателю

### Один вход

Выберите **1**, введите долю ошибок **52**, неточность **12**.
Можно дважды нажать Enter: это значения по умолчанию.

Неточность — полуширина треугольного нечёткого наблюдения. Для 52 и 12 его
носитель [40;64], вершина в 52. Это степень совместимости с наблюдением,
а не распределение вероятности. Если значение известно точно, введите 0.
При точном входе две композиции совпадают; ненулевая ширина позволяет
продемонстрировать различие механизмов.

Программа сама выведет активные правила, их уровни истинности и таблицу:

| Механизм | Импликация | Агрегация | Приоритет |
|---|---|---|---|
| max_min | mamdani | max | 51.3708 |
| max_product | mamdani | max | 51.9548 |
| levels | mamdani | max | 51.3708 |
| levels | larsen | max | 51.3978 |
| levels | mamdani | prob_sum | 51.2039 |
| levels | mamdani | bounded_sum | 51.1700 |

В текущей папке появится `график_один_вход.svg`. Откройте его в браузере.
График содержит кривые выходных множеств и значения центра тяжести.
Повторите с ошибками 15 и 85: результат изменится.

### Три входа

Выберите **2**, введите **52**, **55**, **70**.

- Ошибки — доля неудачных попыток за выбранный период, %.
- Время — длительность попытки запуска, включая завершившуюся ошибкой, с.
- Память — дефицит доступной оперативной памяти, %.

Дефицит = max(0, (нужная память − свободная память) / нужная память) × 100 %.
Если нужно 10 ГБ, свободно 3 ГБ, введите 70. Если дефицита нет — 0.
Программа не измеряет показатели автоматически: их задаёт пользователь.

| Импликация | Агрегация | Приоритет |
|---|---|---|
| mamdani | max | 56.0788 |
| larsen | max | 55.7236 |
| mamdani | prob_sum | 57.4739 |
| mamdani | bounded_sum | 57.5053 |

Откройте появившийся `график_три_входа.svg`.
Чтобы показать влияние каждого входа, повторите пункт 2:

| Ошибки | Время | Память | Приоритет Mamdani/max |
|---|---|---|---|
| 52 | 55 | 70 | 56.0788 |
| 80 | 55 | 70 | 66.6158 |
| 52 | 100 | 70 | 67.4830 |
| 52 | 55 | 95 | 62.6666 |

Все расчёты в пунктах 1 и 2 используют И=min и шаг выхода 0.5.
График соответствующей модели перезаписывается при следующем расчёте.

### Сравнение операторов

Пункт **3**: выберите модель по номеру: single — один вход, multi — три.
Введите данные и выберите агрегацию; для трёх входов также выберите И=min
или product. Программа сравнит четыре импликации. Для одного входа каждая
импликация проверяется тремя механизмами.

Mamdani: min(a,b); Larsen: a*b; Kleene–Dienes: max(1-a,b);
Łukasiewicz: min(1,1-a+b).

Важные случаи для объяснения:

- Для логических импликаций I(0,b)=1. С max-агрегацией нулевые предпосылки
  делают выходное множество постоянным. Центр 50 здесь не означает
  установленный средний приоритет; результат неинформативен.
- С min-агрегацией Mamdani/Larsen пересекаются все заключения. В этой базе
  получается пустое множество; центр тяжести не определён.
- Нулевые предпосылки не исключаются из вычислений.

## Если попросят добавить или изменить правило

Откройте `база_знаний.txt` обычным текстовым редактором.
В нём две отдельные модели: `MODEL single` и `MODEL multi`.

```text
INPUT Ошибки 0 100 52 "%" "Доля неудачных запусков"
TERM умеренные triangle 33.333333 50 66.666667
```

INPUT: имя, минимум, максимум, значение по умолчанию, единица, подпись.
TERM относится к последней объявленной переменной. triangle требует три
числа a,b,c; trapezoid — четыре a,b,c,d. Числа должны идти по возрастанию,
повторы крайних точек допустимы. Вершина имеет принадлежность 1.
OUTPUT задаёт выход: имя, минимум, максимум, единица и подпись.

Правила записаны как в задании:

```text
ЕСЛИ Ошибки=умеренные ТО Приоритет=средний
ЕСЛИ Ошибки=средний И Время=средний И Память=большой ТО Приоритет=повышенный
```

Для безопасной демонстрации сначала сохраните копию базы. В модели single
замените строку `ЕСЛИ Ошибки=умеренные ТО Приоритет=средний` на
`ЕСЛИ Ошибки=умеренные ТО Приоритет=критический`.
Сохраните и выберите пункт 1: ошибки 50, неточность 0.
Результат Mamdani/max станет выше 90 баллов вместо 50.
После демонстрации восстановите исходное правило.

Чтобы добавить правило, допишите строку ЕСЛИ ... ТО в нужной модели.
Используйте уже объявленные переменные и термы; новый терм сначала объявите
после соответствующего INPUT или OUTPUT. Чтобы удалить правило, удалите строку.
Правила одной модели не должны попадать в раздел другой модели.
Изменения учитываются при следующем расчёте без перезапуска программы.
Программа покажет ошибку, если встретит неизвестный терм или неверный формат.

В исходной базе 7 правил для одного входа и 27 для трёх; для сдачи сохраняйте
требуемое количество и покрытие входных диапазонов.

## Как объяснить алгоритм

1. Файл задаёт переменные, нечёткие множества и правила.
2. Фаззификация переводит введённое число в степени принадлежности термам.
3. Для каждого правила рассчитывается α — истинность его условий.
4. Импликация формирует заключение; агрегация объединяет заключения.
5. Центр тяжести переводит итоговое нечёткое множество в число приоритета.

Композиционные механизмы сначала строят отношение R из правил:
max_min использует max_x min(A'(x),R(x,y)), max_product — max_x A'(x)R(x,y).
Уровневый вывод сначала вычисляет α_i, затем агрегирует I(α_i,B_i(y)).
Для одной нечёткой переменной α_i=max_x min(A'(x),A_i(x)); для трёх чётких
переменных — min или product степеней принадлежности условиям правила.
Это три механизма, а импликация и агрегация — отдельные настройки.

## Файлы и проверки

Комплект: программа, база, этот README, отчёт, CSV с 64 результатами и тесты.
Параметры модели учебные; они не получены из статистики реальных приложений.

```bash
python3 -B -m unittest -v
```

Ожидается **24 теста — OK**. Проверяются математические формулы, реальные
изменения внешней базы, ввод, меню и создание корректных SVG.

Для отдельного расчёта доступны команды:

```bash
python3 нечёткая_система.py --model single --values 52 --width 12 --compare
python3 нечёткая_система.py --model multi --values 52 55 70
python3 нечёткая_система.py --model multi --values 52 55 70 --implication larsen --aggregation prob_sum --and-method product
```

`--output путь.json` сохраняет результат одиночного расчёта;
с `--compare --output путь.csv` сохраняется таблица сравнения.
`--base путь.txt` выбирает другую базу, `--step` меняет шаг сетки.
Графики автоматически сохраняются в интерактивных пунктах 1 и 2.
