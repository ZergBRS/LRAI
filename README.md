# Лабораторная работа № 2

Экспертная система с обратной цепочкой рассуждений для диагностики причин,
по которым Python-приложение с PostgreSQL не запускается.

## Запуск

Нужен Python 3.10 или новее. Сторонние пакеты не требуются.
Откройте терминал в папке с файлами и выполните:

```text
python3 экспертная_система.py
```

На Windows можно использовать `python` или `py -3`.

## Файлы

- `экспертная_система.py` — программа и алгоритм обратного вывода.
- `база_правил.txt` — 44 правила для 11 причин отказа запуска.
- `начальные_факты.txt` — сведения, известные перед запуском.
- `целевая_ситуация.txt` — цель по умолчанию.
- `Lr2Ai.docx` — отчёт.
- `README.md` — инструкция.

Файлы правил, фактов и цели должны находиться рядом с программой.

## Меню

1. **Проверить цель.** Enter выбирает стандартную цель; `?` показывает варианты.
   Можно ввести `Причина=неверный_адрес_базы` или другую цель.
   Несколько обязательных целей разделяются связкой `И`.
2. **Показать правила.** Выводит текущие правила с номерами.
3. **Изменить правила.** Внутри: 1 — добавить, 2 — удалить по номеру,
   3 — заменить по номеру, 0 — назад. Изменения сразу сохраняются в файл.
4. **Начальная ситуация.** `Объект=Значение` добавляет или заменяет факт,
   `-Объект` удаляет, пустой Enter возвращает в меню.
   Изменения действуют до завершения программы.
5. **Проверить все причины.** Независимо проверяет каждую гипотезу из базы.
   Показывает подтверждённые, исключённые и не проверенные из-за нехватки данных
   причины, а также рекомендации.
0. **Выход.**

Недостающие исходные сведения программа спрашивает сама: можно ввести номер,
предложенное значение или свой вариант. Enter означает отсутствие сведений.
При нехватке сведений пункт 1 выводит результат и завершает программу.
Ответы пункта 1 относятся к одной проверке; наблюдения пункта 5 остаются в сеансе.
Для постоянного изменения ситуации отредактируйте `начальные_факты.txt`.

## Проверка стандартной ситуации

Выберите 1 и нажмите Enter. Цель `Причина=неверный_адрес_базы` доказывается
правилами 2, 14, 17 и 22. Выводится рекомендация исправить адрес базы.
В пункте 4 задайте `Адрес_базы_верный=да`, вернитесь пустым Enter
и повторите проверку. Прежняя гипотеза будет опровергнута в заданной модели.

## Формат правил

```text
ЕСЛИ Объект1=Значение1 ТО Объект2=Значение2
ЕСЛИ Объект1=Значение1 И Объект2=Значение2 ТО Объект3=Значение3
```

Одно правило занимает одну строку. Названия объектов и значений в правилах,
фактах и целях должны совпадать. Новые правила участвуют в выводе сразу.
Чтобы новая причина появилась в пункте 5, её заключение должно иметь вид
`Причина=новое_значение`.

Программа использует введённые наблюдения и результаты проверок.
Журналы она автоматически не читает и проверяемое приложение не запускает.
